NBX: Compute Platform

Most ML engineers eventually hit the same wall: a local machine is not enough, cloud consoles are too slow, and stitching together SSH commands, environment variables, and artifact downloads by hand does not scale. NBX is a production-grade compute platform built to solve this — a system with a machine registry, a task queue, a live monitoring dashboard, and multi-provider dispatch where submitting a training job to a RunPod pod, an AWS instance, or a bare SSH host looks and feels identical, and where progress, logs, and outputs stream back to a local Flet UI in real time. This mini-series builds NBX from scratch.

About This Series

Goal. To build a real, deployable ML compute platform — not a toy — from the first design sketch through a working multi-provider system. Every abstraction is motivated, every design choice is justified, and the resulting codebase is something you could extend and put into production.

Audience. ML engineers and practitioners who have worked through the main App Development series (or have equivalent experience with FastAPI, Docker, and async Python). You are comfortable building backend services and want to apply that skill to real research infrastructure — not another tutorial CRUD app, but a platform you would actually use.

Stack. Flet for the live resource-monitoring dashboard UI, FastAPI for the REST and WebSocket layer, asyncssh for remote command execution, papermill for parameterized notebook runs, pydantic-settings for config and secrets management, and RunPod / AWS / bare SSH as interchangeable provider targets.

Course Notebooks

# Title Key Topics
NBX:01 Platform Architecture System design principles, provider abstraction layer, job spec schema, pydantic-settings config, secrets management, project scaffold
NBX:02 Registry & Dashboard Provider adapter pattern (RunPod / AWS / SSH), machine CRUD API, async health polling, Flet live resource dashboard with CPU / RAM / disk charts
NBX:03 Job Packaging & Execution tar.gz packaging, rsync-based sync, Runner abstraction (notebook / script / project), papermill param injection, SSH remote execution via asyncssh
NBX:04 Task Queue & Dispatch asyncio.PriorityQueue internals, job lifecycle FSM (pending → running → done / failed), provider selection strategy, parallel job concurrency control
NBX:05 Log Streaming & Artifacts WebSocket log fan-out, subprocess stdout / stderr capture, structured log events, artifact download via SCP, job history persistence, dev-mode file watching

Prerequisites

  • 05 — FastAPI Fundamentals: routing, Pydantic models, dependency injection, async handlers
  • 06 — Docker & Local Infrastructure: container lifecycle, docker-compose, environment configuration
  • 12 — Realtime Data & WebSockets: WebSocket protocol, pub/sub fan-out, async streaming patterns
  • SSH basics: key-based authentication, ~/.ssh/config, remote subprocess execution
  • Cloud account (optional): RunPod or AWS credentials for the provider adapter exercises; all core mechanics work over plain SSH

How to Read This Series

If you want to understand the architecture first: Read 01 carefully before anything else. The provider abstraction and job spec schema established there underpin every subsequent notebook.

If you are here for the Flet dashboard: 02 is the most UI-heavy notebook. It stands alone if you already understand the MachineRegistry concept from 01.

If you care about remote job execution: 03 and 04 are the core. Read them in order.

If you want the full streaming story: 05 builds on all prior notebooks; read it last.
